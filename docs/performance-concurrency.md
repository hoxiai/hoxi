# 多任务并发与会话缓存

## 隔离边界

- 任务启动、压缩、回滚、切换运行时和沙箱变更按会话串行；不同会话使用独立锁。锁等待者退出后回收锁条目
- 消息存储按会话锁定，读盘、写盘、日志整理和正文序列化不持有全局注册表锁。全局锁只保护会话索引与独立的元数据快照
- 日志回放及流式更新使用消息、片段索引，避免逐条回扫历史。任务结束只刷新自己的正文；子任务结束或中止时单独刷新并解除缓存保护
- 写盘失败时保留最新消息状态和未落盘增量，重试成功前不淘汰正文。同一片段的失败快照合并，避免重复保留不断增长的文本

## 正文内存预算

前后端均采用最近使用顺序回收闲置正文，预算为 12 个会话、约 32MiB 正文载荷。字节预算是估算值，不代表进程总内存上限

- 后端在正文访问完成后维护缓存，运行中的会话不参与淘汰
- 前端每 4 秒维护一次缓存，保留当前会话及其子任务、运行或重试中的会话、审批或问答中的会话、正在读取的历史及尚未发送的乐观消息
- 前端回收正文时同步取消该会话的 Diff 刷新并作废在途响应，保留会话元数据、草稿、模型选择和未读状态
- 再次打开已回收的会话时从本地后端重新加载；后台事件生成的局部正文不能被当作已完整加载的历史
- 当前任务和运行中的任务可以超过缓存预算，任务内容不会因此截断

## 长任务展示与事件恢复

长任务窗口保留用户提示和当前工具组的原有锚点，默认展示最近的步骤，避免为找回提示而挂载整个任务周期。初始 12 条窗口最多额外回溯 12 条，并携带最多两个上下文行；历史可以按需展开

工具组展开时默认挂载最近 40 个片段，按 40 个递增加载。收起时卸载明细；搜索定位可以主动展开历史

事件订阅队列维持 512 条上限。客户端滞后导致溢出时丢弃过期队列并发送 `hoxi.stream.resync`，执行进程不等待客户端腾出空间。前端补读会话列表、状态、权限、问答和已驻留正文，正文补读最多并行 4 个；运行中的会话也参与补读

## 模拟场景对比

以下为开发机上的临时模拟测试，不调用真实模型。历史读取每条消息含 1KiB 文本，耗时为 3 次平均，文件系统缓存已预热

| 场景 | 修复前 | 修复后 |
| --- | ---: | ---: |
| A 会话压缩延迟 800ms 时，B 会话切换运行时 | 804ms | 0.44ms |
| 3 个事件订阅队列堵塞时的操作耗时 | 153ms | 0.30ms |
| 10,000 条消息首次读入内存 | 200ms | 55ms |
| 10,000 条历史后的 1,000 次增量追加 | 18.8ms | 0.66ms |
| 打开 20 个约 1.56MiB 正文的会话，GC 后后端堆增量 | 39.9MiB | 24.4MiB |
| 同一提示后的 1,000 个推理步骤，初始窗口挂载行数 | 1,001 | 26 |

这些数据验证阻塞路径、缓存回收及渲染窗口上限，不能推导真实 CLI 并发上限或 WKWebView 帧率
