# Embedded Browser Plugin

`PrepareBrowserPlugin(baseURL, token string) (env []string, cleanup func(), err error)`
materializes the embedded standalone plugin in a private temporary directory (0700),
with `plugin.mjs` mode 0600. Append the returned environment overrides to the
OpenCode child environment; keep the directory until the child exits, then call
`cleanup`. The helper does not change the current process environment or any user
config files. It preserves the inline config's plugin entries (including tuples),
appends the temporary file URL, and sets the config schema. Invalid/non-object
inline JSON and non-array plugin lists are rejected rather than discarded.

App/daemon/gateway integration is now installed: the runtime supplies the browser
service base URL and matching agent token and installs this overlay for the
OpenCode child. A newly prepared overlay takes effect when the child starts, not
in an already running process. Restart the app/OpenCode child after plugin changes.

After config loading, the plugin's config hook forces `permission.hoxi_browser`
to `"ask"`, preserving all other permission fields. String permission shorthand
becomes a `"*"` rule with the original value. The browser rule is placed last so
an inherited wildcard allow cannot silently auto-pass `context.ask` requests.

## Regeneration

From the repository root with Node on `PATH` (plugin SDK 1.18.25 in
`.opencode/node_modules`):

```sh
NODE_PATH="$PWD/.opencode/node_modules" web/node_modules/.bin/esbuild internal/opencode/browser_plugin.js --bundle --platform=node --format=esm --target=node20 --minify --legal-comments=none --banner:js='// Code generated by esbuild from browser_plugin.js; DO NOT EDIT.' --outfile=internal/opencode/browser_plugin.mjs
```

The generated asset includes zod and the SDK tool wrapper, has no runtime package
dependencies, and is embedded by Go. Never hand-edit it. Regenerate after changes
to the source or installed SDK. Only the default plugin factory is exported.

```sh
go test ./internal/opencode -run Browser
node --test internal/opencode/browser_plugin_test.mjs
```

The JavaScript tests import the actual standalone bundle with mocked fetch and
execution contexts; no live OpenCode server or Chrome installation is needed.
